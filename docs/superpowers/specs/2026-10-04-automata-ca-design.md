# Automataへの既存セル・オートマトンの統合

## 目的と合意した範囲

既存のCHROMALUM CA Labを、CHROMALUM本体のReact画面として移植する。メインタブ名は日英ともに **Automata** とし、TheoryとMusicの間に置く。初版は、現在の一次元・二次元の機能、本体に揃えたUI、操作状態の保存を提供する。

成功条件は、利用者がAutomata内で初期配置と規則を選び、ステップを進め、8色とチャンネル表示の対応を確認できること。同じ入力から既存版と同じ結果が出て、タブ切り替えと再読み込み後にも編集を続けられることを確認する。

Boolean Network、Sourceへの模様送付、自動再生は今回の実装範囲に含めない。これらは統合版を操作したあとで検討する。

## 状態空間と更新規則

各セルは `A = {0,1}³` の一状態であり、GRB順の3ビットを0〜7で符号化する。色とコードは `K=000, B=001, R=010, M=011, G=100, C=101, Y=110, W=111` とする。計算・初期配置編集・チャンネル表示は、この離散状態に対して行う。

GRB Binary Toneの順位とビットの場所、知覚的明るさ、純色相環上の連続色候補は区別する。Hex／Glazeの色候補や連続RGB値はCAの演算に入力しない。XORはビット反転の合成と相殺であり、物理的な混色の説明には使わない。

CAの規則は、この状態空間に追加する選択である。規則がCHROMALUMの代数から一意に導かれる、またはCA自体が本プロジェクトの新規発明であるという説明は加えない。研究ノートにある数学的主張と既存Theoryの文章は変更しない。

### 一次元

- 65セル、時刻 `t=0..48`。範囲外はK。全セルを現在時刻の値から同時に更新する。
- Rule 90：`next[i] = current[i-1] XOR current[i+1]`。
- Rule 150：`next[i] = current[i-1] XOR current[i] XOR current[i+1]`。
- 独立モードは各チャンネルに同じ基本ルールを適用する。
- 結合モードでは、基本ルールの結果を、現在の中央セルから得るマスク `((r AND b) << 2) XOR ((b AND g) << 1) XOR (g AND r)` で反転する。他の2チャンネルがともに1の場合に、そのチャンネルの結果を反転する既存仕様を保つ。
- 比較モードは、同じ初期配置・基本ルールから独立と結合の両方を表示する。
- 表示は8色、またはG・R・Bに分解した3段表示。横軸は位置、縦軸は時間。
- 初期配置は「彩りの波紋」「光の三重奏」「G・R・Bを別々に置く」「白1セル」「すべて黒」の5種類。白1セルを選ぶと時刻を1にする。それ以外のプリセット変更では時刻を保つ。
- 初期列のクリックは選択セルを変える。位置入力とG・R・Bのチェックボックスで初期状態を編集する。履歴のクリックは状態の読み取りに使う。
- 「配置を戻す」は、現在のプリセットから初期列を再生成する。時刻・規則・表示方法は保つ。
- 「1ステップ進む」は時刻を1増やし、48で無効になる。

### 二次元

- 49×49セル、時刻 `t=0..20`。範囲外はK。全セルを同時に更新する。
- XOR規則は、十字4セル、十字＋中央5セル、斜め4セル、斜め＋中央5セル、周囲8セル、周囲＋中央9セルの6種類。
- ライフゲームはチャンネルごとにB3/S23を適用する。
- 「ペルシャ絨毯」は既存UIの名称を保ち、チャンネルごとにB234/Sなしを適用する。現在0のセルは周囲の1が2・3・4個のときに1となり、現在1のセルは次に0となる。
- 初期配置は `rosette, diamond, corolla, luminous, clock, phase-clock, pulse, fireworks, weave, rgb, white, black` の12種類。名称と配置を引き継ぐ。
- プリセット変更は選択座標を中央に戻す。`rosette, diamond, corolla, luminous, rgb` は時刻7、その他は時刻0にする。選択した規則は保つ。
- 表示は8色、G、R、B。初期配置と現在の配置を同じセル寸法で並べる。
- 初期配置のクリックは、選択座標の変更と選択色の配置を行う。現在の配置のクリックは読み取りのみ。座標入力・色選択・「このセルに色を置く」でも同じ編集ができる。
- 「1ステップ進む」は時刻を1増やし、20で無効になる。

## 本体への接続と責務

タブIDとURLハッシュは `automata` とする。`src/tabs.ts` の `MAIN_TABS` に追加し、既存のタブIDによるタイトル・保存・履歴移動・キーボード操作に接続する。旧タブ番号の互換表は固定された旧順序を保ち、新しいタブ順から再生成しない。

画面は初回に開いたときに遅延読み込みし、その後はタブを隠しても状態を保持する。非表示中はCanvasの計測と描画を停止し、表示されたときに現在のコンテナー幅で描き直す。状態保存が使えない場合も、同じアプリ起動中のタブ切り替えでは編集を保持する。

責務は次の単位に分ける。ファイル名は実装計画で固定するが、境界はこの設計に従う。

| 単位                     | 責務・入出力                                                                                    |
| :----------------------- | :---------------------------------------------------------------------------------------------- |
| CAモデル                 | 状態列／盤面、規則、時刻から履歴／結果を返す純粋関数。入力を書き換えず、DOMと保存先に依存しない |
| 初期配置データ           | プリセットIDと固定寸法から0〜7の配置を生成する。表示文言は翻訳側に置く                          |
| 状態と保存               | 一次元・二次元の状態、操作による更新、保存値の検証と復元を担当する                              |
| Canvas描画               | 状態データと描画寸法から描画し、クリック座標をセル座標へ変換する                                |
| AutomataPanel            | 盤面選択、見出し、保存状態の通知を担当し、一次元・二次元の操作画面をまとめる                    |
| 一次元・二次元の操作画面 | ネイティブ入力とボタン、配置編集、読み取り結果、凡例を表示する                                  |

初期配置と規則の変更で計算を更新する。チャンネル表示・選択セルだけの変更では、同じ計算結果を再利用する。結果の盤面や履歴は保存値に含めず、初期配置と規則から再計算する。

新しい依存パッケージ、別HTMLエントリー、バックエンドは追加しない。通常の本体ビルドに含め、既存のプロトタイプ用ビルド設定は使わない。

## 保存と失敗時の振る舞い

保存先はAutomata専用の `localStorage` キー `chromalum-automata-state-v1` とし、Source／GlazeのIndexedDB保存と分ける。ここでのv1は内部データ形式の識別子であり、製品のリリース番号ではない。

保存内容は、盤面種別と、一次元・二次元それぞれの初期配置、プリセット、規則、表示方法、時刻、選択位置、二次元の配置色。保存データには形式の識別値を含める。

復元時は、許可した文字列、整数範囲、配列の長さ、各セルが0〜7であることを検証する。不正な項目は、その項目または該当配置だけを既定値へ戻し、妥当なもう一方の盤面と設定は保つ。未知の形式やJSONの破損は初回の既定値に戻す。

保存を拒否された場合も画面は動作し、メモリー内の状態を保持する。保存失敗が実際に起きたときは、再読み込み後の復元ができないことを非モーダルの通知で伝える。

移植元の `window.openai.widgetState` と本体の保存先は別である。本体は新しいキーから復元し、既存プレビューの保存状態はそのまま残す。この初版に外部プレビューからの自動取り込み機能は設けない。

## 表示・操作・アクセシビリティ

新規スタイルはすべて `src/styles/global.css` に置き、既存の色・文字・間隔のトークンを使う。見出しはAutomata、その下にCellular Automatonの操作画面を置く。UIと読み取り用ラベルを日英に対応させ、数式・GRB・Rule番号の表記を保つ。

幅に応じた配置はコンテナークエリーと `clamp()`／`cqw` を使う。広い画面では独立と結合、二次元の初期配置と現在を横に並べ、狭い画面では縦に積む。8タブのナビゲーションも最小幅で検証し、ラベルを切らず、折り返した場合の高さを選択中のタブによらず一定にする。

一次元の履歴は最大49行分の描画領域を最初から確保し、選択時刻を超える行は結果として描かず、読み取り対象にもしない。時刻だけが変わる操作ではCanvasを作り直さない。GRB分解と比較表示は共通の幅からセル寸法を算出する。

二次元の初期配置と現在は共通の寸法を使い、ステップを進めてもCanvasと凡例の位置を保つ。サイズ変更と表示再開は `ResizeObserver` で再計測する。Canvasのデバイスピクセル比の調整は、CSS上の描画寸法と独立させる。

Canvasには意味のあるラベルを付け、選択した位置・時刻・色・GRBコードをDOMの読み取り欄にも表示する。座標入力、チェックボックス、色選択、ボタンで配置編集を完結できる。読み取り欄の重要な変更は `aria-live="polite"` で伝える。

グローバルな描画ショートカットがAutomataの入力を奪ったり、Sourceの画像を変更したりしないことを確認する。タブの矢印・Home・End、ハッシュによる直接表示、ブラウザーの戻る／進むを既存仕様に合わせる。

この初版は明示的なステップ操作を使う。選択時刻の更新にモーションを追加しない。

## 検証と受け入れ条件

### 計算と保存

- 独立Rule 90／150の結果を、チャンネル別の二値更新と突き合わせる。境界外K、同期更新、入力の不変性を検証する。
- 結合モード、各初期配置、二次元の全8規則を、移植元から固定した期待値と比較する。ライフゲームの既知の固定点と周期、外側Kの小さな盤面も使う。
- 一次元と二次元を交互に編集し、時刻・初期配置・規則・表示・選択セルを保って切り替えられることを確認する。
- 保存と復元の往復、不正な保存項目、配列長の不一致、保存拒否を確認する。片方の不正データで、もう一方の正常な編集を失わないことを検証する。

### 本体とブラウザー

- `#automata` で直接開ける。タイトルは `CHROMALUM - Automata`。日英ともタブ名はAutomata。
- 日英切り替えで操作状態を保ち、全ての新しい翻訳キーとラベルを確認する。
- 別タブへ移動して戻る操作と、再読み込みの両方で状態を復元する。Source／Glazeの保存内容に変更がないことも確認する。
- 一次元・二次元とも「1ステップ進む」の前後で、操作部、Canvas、凡例の矩形を測定する。時刻のみの更新による位置・寸法の変化を許容しない。
- 広い画面と320〜390px程度の縦長画面、比較表示、GRB表示で、横にはみ出し・文字の重なり・操作対象の重なりを確認する。MS Gothicなど幅広の字形でもラベルが収まることを検証する。
- キーボードだけでタブ移動、規則選択、初期配置編集、ステップ操作ができる。タブの追加に影響する既存e2eとアクセシビリティの期待値を更新する。
- 新しい計算テストと関連e2eを通した後、`npm run verify`、`npm run test:e2e -- --workers=2`、`npm run test:pwa` を実行する。e2eの失敗は対象を `--workers=1` で再確認する。PRのカバレッジゲートは別途 `npm run test:coverage` で確認する。
